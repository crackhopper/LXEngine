# 02. 3DGS 渲染算法

> 状态：已立项
> 调研日期：2026-05-28
> 对应需求：`REQ-063-a`

## 从空间椭球到屏幕椭圆

3DGS 的每个 primitive 是一个三维 Gaussian。我们可以把它理解成空间里的半透明椭球印章。渲染时把椭球投影到屏幕，得到一个二维椭圆 footprint，再对覆盖像素计算 Gaussian 权重和 alpha。

| 参数 | 来源字段 | 渲染意义 |
|---|---|---|
| mean | `x/y/z` | Gaussian center |
| scale | `scale_0..2` | 椭球三轴尺寸，PLY 中通常是 log-scale |
| rotation | `rot_0..3` | 椭球朝向，四元数 |
| covariance | scale + rotation | 3D Gaussian 形状矩阵 |
| opacity | `opacity` | alpha 的 raw 参数，通常 sigmoid 后使用 |
| color | `f_dc_*` / `f_rest_*` | 球谐颜色，首版可只使用 DC |

Open3D 的 3DGS 设计文档明确把 PLY log-scale 在加载时转为 linear scale，把 opacity sigmoid 映射后打包，并用 `R S S^T R^T` 构造 3D covariance。这个做法适合 LXEngine：CPU 侧只做一次激活和打包，shader 每帧少做重复工作。

## 排序与合成

3DGS 是透明体渲染。没有正确顺序时，颜色会发灰、闪烁或出现错误遮挡。

| 路线 | 做法 | 适合阶段 |
|---|---|---|
| CPU view-depth sort | 每帧按 camera view depth 排 splat index | 首版，易实现 |
| Worker / job sort | WebGL viewer 常见路线，把排序移出主线程 | 有 job system 后 |
| GPU tile/radix sort | 每个 splat 生成 tile entry，再 radix sort | 高性能阶段 |

Open3D 使用投影、tile sort、composite 的 GPU compute pipeline。antimatter15 的 WebGL viewer 用 worker 做深度排序和 GPU-friendly data packing。LXEngine 当前还没有 3DGS 专用 compute/tile sort 基础，因此首版选择 CPU sort 是合理的实施策略。

## 首版渲染闭环

首版应该追求可见、稳定、可验收：

```text
GaussianSplatCloud
  -> CPU 激活 scale / opacity
  -> 每帧按 view depth 排序
  -> 上传 sorted indices 或重排 draw 数据
  -> Vulkan splat pass
  -> alpha blended HDR scene color
```

| 能力 | 首版要求 | 后续优化 |
|---|---|---|
| 颜色 | `f_dc` base color | degree 1-3 SH |
| 排序 | CPU back-to-front | GPU tile/radix |
| footprint | scale + rotation 投影 | anti-aliased / mip-splatting |
| 合成 | alpha blending | front-to-back transmittance compute |
| mesh occlusion | 可暂不支持 | depth-aware composite |

## 风险

| 风险 | 处理 |
|---|---|
| CPU 排序大场景耗时 | 首版只要求 741k splat 样例可交互；记录性能指标 |
| alpha 顺序错误 | 验收必须 orbit 后截图仍合理 |
| PLY raw 参数解释不一致 | loader 记录 raw 和 activated 两层字段 |
| 高阶 SH 未启用 | resource 不丢弃 `f_rest`，文档明确首版限制 |
